1. CPU Scheduling Calculations (Sample Workload)
-----------------------------------------------
Workload:
P1: AT = 0,  BT = 5, Priority = 3
P2: AT = 1,  BT = 3, Priority = 1
P3: AT = 2,  BT = 8, Priority = 4
P4: AT = 3,  BT = 6, Priority = 2
P5: AT = 15, BT = 4, Priority = 2

A. FCFS (First-Come, First-Served)
- Timeline: P1 (0-5) -> P2 (5-8) -> P3 (8-16) -> P4 (16-22) -> P5 (22-26)
- Completion Times (CT): P1=5, P2=8, P3=16, P4=22, P5=26
- Turnaround Time (TAT = CT - AT):
  P1: 5 - 0 = 5
  P2: 8 - 1 = 7
  P3: 16 - 2 = 14
  P4: 22 - 3 = 19
  P5: 26 - 15 = 11
  Average TAT = (5 + 7 + 14 + 19 + 11) / 5 = 11.20
- Waiting Time (WT = TAT - BT):
  P1: 5 - 5 = 0
  P2: 7 - 3 = 4
  P3: 14 - 8 = 6
  P4: 19 - 6 = 13
  P5: 11 - 4 = 7
  Average WT = (0 + 4 + 6 + 13 + 7) / 5 = 6.00
- CPU Utilization: 26 / 26 = 100%

B. SJF (Shortest Job First - Non-Preemptive)
- Timeline: P1 (0-5) -> P2 (5-8) -> P4 (8-14) -> P3 (14-22) -> P5 (22-26)
- Completion Times (CT): P1=5, P2=8, P4=14, P3=22, P5=26
- Average TAT = (5 + 7 + 20 + 11 + 11) / 5 = 10.80
- Average WT  = (0 + 4 + 12 + 5 + 7) / 5 = 5.60

C. SRTF (Shortest Remaining Time First - Preemptive SJF)
- Timeline: P1 (0-1) -> P2 (1-4) -> P1 (4-8) -> P4 (8-14) -> P3 (14-15) -> P5 (15-19) -> P3 (19-26)
- Preemptions:
  - At t=1, P2 arrives (BT=3 < P1 remaining=4) -> preempts P1
  - At t=15, P5 arrives (BT=4 < P3 remaining=7) -> preempts P3
- Average TAT = (8 + 3 + 24 + 11 + 4) / 5 = 10.00
- Average WT  = (3 + 0 + 16 + 5 + 0) / 5 = 4.80
- Average RT  = (0 + 0 + 12 + 5 + 0) / 5 = 3.40

D. Round Robin (q=2)
- Execution Order: P1 -> P2 -> P3 -> P1 -> P4 -> P2 -> P3 -> P1 -> P4 -> P3 -> P5 -> P4 -> P3 -> P5
- Average TAT = 15.20
- Average WT  = 10.00
- Average RT  = 2.20 (Lowest response time due to regular time-slicing)

2. Observations on System Calls, Processes, Threads, and IPC
------------------------------------------------------------
- System Calls:
  Low-level calls (open, read, write, close, getpid) switch execution from
  user mode to kernel mode via the syscall software trap. The OS kernel handles
  the requested device/filesystem action and returns control back to user space.

- /proc Filesystem:
  The /proc directory is a virtual filesystem in Linux RAM providing access
  to internal kernel data structures. /proc/[pid]/status allows monitoring of
  process state (R for running, S for sleeping, Z for zombie), memory usage
  (VmRSS), and voluntary vs involuntary context switches.

- Zombie and Orphan Processes:
  - Zombie: When a child exits, its memory is freed but its entry in the process
    table remains until the parent calls wait()/waitpid() to read its exit code.
  - Orphan: If the parent terminates first, the child is adopted by init/systemd
    (PID 1 or user systemd manager).

- Process vs Thread:
  - Processes have separate memory spaces (demonstrated via fork copy-on-write).
    Changes in child memory do not modify parent variables.
  - Threads share the same address space and heap. Without synchronization
    (e.g., threading.Lock), concurrent access to shared variables produces race
    conditions (lost updates).

- IPC Mechanisms:
  - Pipes (os.pipe): Unidirectional byte stream between related processes.
  - FIFO / Named Pipes (os.mkfifo): Filesystem-backed pipe allowing unrelated
    processes to communicate using standard file descriptors.
  - Shared Memory: Fast zero-copy communication across processes; requires explicit
    locks (Lock) to prevent race conditions.
  - Message Queue: Structured message passing with built-in process synchronization.
  - Signals (os.kill): Asynchronous notification mechanism.
